# 复杂工作区保护与 Dashboard 数据新鲜度

## 实现范围

- 统一 `useFormSafety`，接入 34 个表单：服务器、节点、服务器节点覆盖、全局节点配置、商品、订阅配置/应用、用户创建、用户资料与订阅编辑、优惠券、支付、文档、公告、广告、营销邮件/配额、系统及认证配置。
- 关闭按钮、取消、外部关闭、浏览器返回或路由跳转触发未保存确认；刷新/关闭浏览器使用原生离开提示。保持编辑或明确放弃后才继续。
- 校验失败在表单顶部显示错误摘要。协议折叠区及商品/节点配置 Tabs 标记字段路径，点击错误项会先打开对应区域，再滚动、聚焦控件。
- 保存前确认修改字段；协议按协议类型、数组配置按索引区分。清单不展示字段值，不将密码、私钥、Token 或其他表单内容写入 localStorage/sessionStorage。
- 防止重复提交，取消保存确认不发请求；提交失败保留输入。保留原有 API、规范化处理、相关表格刷新和配置 Query 的 refetch，成功后更新本地基线。
- 配置重新获取时不覆盖正在编辑/提交的内容。稳定 ProTable 内置操作列的渲染器，避免普通表格重绘卸载行内弹层；保留原有菜单与焦点恢复逻辑。
- 用户资料长表单的关闭保护接入所属窗口，切换资料 Tabs 保留输入；钱包仍只提交实际修改字段。独立的四个通知开关属于短卡片，保留原有提交行为。

## 数据口径与新鲜度

- 收入、用户、服务器/流量、待回复工单分别使用各自 Query 的 `dataUpdatedAt`，不再用最大时间代表整页同步完成。
- 时间表示前端最近成功取数时间，不等同于后端统计任务截止时间或节点最后心跳；本轮没有新增后端数据时效字段。
- 流量、在线用户、节点摘要和健康卡片来自同一个服务器统计响应，共享其时间；不会虚构它们拥有独立请求或更新时间。待处理卡片分别显示服务器与工单来源。
- 系统服务显示版本请求的新鲜度；可见且活跃时纳入全局刷新。静态系统操作和项目支持不冒充统计来源。
- 有旧数据时，刷新期间继续显示并标注；失败显示“刷新失败 · 显示上次数据”，时间仍为上次成功时间。首次失败或缺失值显示 `—` / 不可用，不使用 0 代替；真正的 0 仍正常显示。
- 全局刷新只刷新相关统计与活跃版本来源，等待全部结果；检查 `refetch()` 返回的错误状态（不仅检查 Promise 是否 reject），报告全部更新、部分失败或全部失败。
- 现有布局、主题、动效、排行、登录和 API 合同保持不变；上一批偏好设置与移动详情的修改予以保留。

## 验证方式

- Admin 完整测试包含表单离开/保留/放弃、原生离开、敏感值不泄露、不写草稿、保存失败与重试、重复提交、错误聚焦、真实 Hash Router 阻止导航、表格刷新保留弹层、钱包字段、Reality Schema、Locale、日志返回等回归。
- 新鲜度测试覆盖真实 0、无数据、首次失败、缓存值刷新失败，以及部分请求 reject/部分 resolve 错误、等待全部数据源完成。
- 浏览器：运行 `scripts/check-admin-form-freshness-browser.mjs`，连接本地生产预览和 Mock API；检查 390/430/768/1024/1280/1440px 的英文浅色与中文深色，中文启用减少动态效果。
- 浏览器模拟部分刷新失败、首次全部统计失败、恢复成功；核对旧值/原成功时间保留、新来源时间更新、初次失败不显示假 0，以及节点配置的取消、返回、确认、失败保留和再次保存。
- Mock 验证不等于真实后端联调，也不代表真实低性能手机硬件验收。没有变更后端、Swagger、客户端或 User Web 页面代码。

## 本轮结果

- Admin：49 个文件、222 项测试通过；UI：8 个文件、39 项通过；User：17 个文件、81 项通过，共 342 项。
- Admin/User TypeScript 与生产构建通过；Biome 检查 506 个文件通过；Locale 对称和 `git diff --check` 通过。
- 新功能浏览器矩阵 12/12 通过，覆盖上述六种尺寸、两种语言/主题组合和减少动态效果；不将这一矩阵描述成所有状态的笛卡尔积。
- 用户资料补充接入后，钱包/表单安全定向 10 项通过，390/1440px 的中英文资料关闭与跨 Tabs 保留补充检查 4/4 通过；此前个性化、移动流量详情、保存视图的浏览器回归 12/12 通过。
- 构建保留现有 `eval` 与大 chunk 警告，本轮没有扩大范围重写运行时脚本或拆包配置。
